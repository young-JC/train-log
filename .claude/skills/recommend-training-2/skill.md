# recommend-training-2.0

为 `train2.0` 生成今日篮球运动员训练建议。

## 1. 职责与硬性约束

适用于“推荐今天训练什么”“今天该怎么练”“根据状态或膝盖情况安排训练”“更新 Readiness”“根据最近训练调整计划”或“从动作库选择今日动作”等请求。

本技能负责：

1. 确认日期并采集当日状态；
2. 计算 Readiness 并确定训练权限；
3. 结合周期、计划槽位、近期刺激、恢复和弱点生成推荐；
4. 同步每日 Readiness 与 Dashboard 今日推荐。

训练结束后使用 `record-training-2` 记录实际完成内容。**推荐计划不得写成正式训练记录。**

### 固定配置与事实源

- 12 周周期开始日期：`2026-09-21`。
- 默认计划：`train2.0/12周计划安排.md` 的 **3 日版**。
- 正式训练记录唯一事实源：`train2.0/records/YYYY-MM.md`。
- 训练趋势速查索引：`train2.0/records/00_摘要.md`（每次训练一行，非事实源；以月度记录为准）。
- 弱点管理唯一事实源：`train2.0/weakness-tracking.md`。
- 动作唯一事实源：`train2.0/动作库/`（`00_索引.md` 负责筛选路由，`A_活动度.md` … `Q_训练后整理与拉伸.md` 共 17 本分册负责动作详情）。
- Dashboard：`train2.0/dashboard.html`（外壳）+ `train2.0/assets/`（样式与数据）。
- `train2.0/archive/` 是拆分前原件与历史版本，**不是事实源，不得读取或引用**。
- 月度 HTML 与 Dashboard 都是展示层。
- 不读取旧 `localStorage` 作为正式训练历史，不迁移或调用 `train1.0/` 补齐历史。

所有结论必须可追溯到用户明确输入、正式训练记录、12 周计划、训练理念、动作库、弱点追踪或已有训练表现。不得推测或编造 Readiness、疼痛、恢复程度、重量、组次、动作表现、Session Load、跳跃/冲刺成绩或改善结论。

### 术语显示

面向用户和 Dashboard 的训练术语使用 **中文（英文）**，动作名称使用 **中文动作名（英文动作名）**，不得在主要展示区域只写英文。常用术语包括活动度（Mobility）、防伤训练（Prehab）、落地控制（Landing）、减速制动（Deceleration）、增强式训练（Plyometric）、爆发力（Power）、力量（Strength）、速度（Speed）、变向（Change of Direction, COD）、核心抗旋转（Anti-Rotation）、全身力量传递（Kinetic Chain）、主观用力程度（RPE）和剩余次数（RIR）。

### 唯一决策顺序

正式推荐必须依次判断：

```text
红旗症状
→ 疼痛权限
→ Readiness
→ 当前 12 周周期
→ Deload / 测试要求
→ 本周尚未完成槽位
→ 最近 48–72 小时刺激暴露
→ 同类训练恢复间隔
→ Session Load / RPE 与疼痛趋势
→ P1 / P2 / P3 弱点
→ 今日能力与动作模式
→ 动作 Level
→ 动作进退阶链
→ 刺激预算
→ 最少必要动作
→ 生成训练与 Quality Stop
```

先决定今天需要训练的能力，再确定刺激和动作模式，最后选择具体动作；不得因为某个动作看起来好就将其塞入训练。

## 2. 阶段 1：确认日期并采集 Readiness

### 日期

1. 用户明确日期时使用用户日期；用户说“今天”且无歧义时使用当前日期。
2. 系统日期与用户语境明显冲突时先确认。
3. 日期早于周期开始日或晚于第 12 周时，不得擅自循环周期；询问用户选择延续当前周期、开始新周期或仅做临时训练推荐。

### 五项输入

| 指标 | 范围 | 方向 |
|---|---:|---|
| 睡眠 | 1–5 | 越高越好 |
| 当前疲劳 | 1–5 | 越低越好 |
| 当前酸痛 | 1–5 | 越低越好 |
| 当前疼痛 | 0–10 | 越低越好 |
| 当前训练意愿 | 1–5 | 越高越好 |

采集规则：

- 只使用用户明确提供的数据，不自行打分。
- 缺少输入时一次最多追问 2–3 项；收到回答后再检查剩余项。
- 五项未齐全时可以初步分析，但不计算正式 Readiness，也不输出正式训练计划。
- 数值超出范围时请用户重新确认，不自动截断。
- 疼痛大于 0 时记录部位、性质、是否影响动作、是否比平时明显增加。
- 尖锐痛、明显肿胀、卡顿、关节不稳或打软腿、明显跛行、活动范围明显下降、疼痛持续恶化，均标记为红旗。
- 本技能不进行医学诊断。

## 3. 阶段 2：计算 Readiness 与安全权限

使用等权公式：

```text
Readiness = round(20 × (
  睡眠 / 5
  + (6 - 疲劳) / 5
  + (6 - 酸痛) / 5
  + (10 - 疼痛) / 10
  + 训练意愿 / 5
))
```

结果范围为 `0–100`。Readiness 用于确定训练权限区间，不把 82 与 79 等小差异解释成精确生理意义。

| 等级 | 条件 | 训练权限 |
|---|---|---|
| 绿色 | ≥75 且疼痛 ≤2 且无红旗 | 可以执行计划训练，再结合近期负荷调整 |
| 黄色 | 60–74，或疼痛 3–4，且无红旗 | 总量减少约 20%–30%，降低冲击、复杂度或容量 |
| 红色 | <60，或疼痛 ≥5，或存在红旗 | 取消跳跃、冲刺、高速变向和疼痛相关负重 |

权限优先级始终是：

```text
红旗 > 疼痛权限 > Readiness 总分
```

不得因为总分高而突破疼痛限制。存在红旗时暂停相关训练，并建议寻求运动医学或康复专业人员评估。

## 5. 阶段 4：确定周期位置与本周槽位

以 `2026-09-21` 为 Week 1 Day 1，按连续 7 天计算周次。

| 周次 | 大阶段 | 4 周内任务 |
|---|---|---|
| W1 | 基础重建（Foundation） | 进入 / 适应 |
| W2 | 基础重建（Foundation） | 增量 |
| W3 | 基础重建（Foundation） | 高刺激 |
| W4 | 基础重建（Foundation） | Deload + 测试 |
| W5 | 力量 → 爆发（Strength → Power） | 进入 |
| W6 | 力量 → 爆发（Strength → Power） | 增量 |
| W7 | 力量 → 爆发（Strength → Power） | 高刺激 |
| W8 | 力量 → 爆发（Strength → Power） | Deload + 测试 |
| W9 | 篮球运动表现（Performance） | 进入 |
| W10 | 篮球运动表现（Performance） | 专项强化 |
| W11 | 篮球运动表现（Performance） | 高质量峰值 |
| W12 | 篮球运动表现（Performance） | Taper + 测试 |

Deload 永远优先于“最近状态很好所以再加量”。

默认 3 日版槽位：

| 槽位 | 主题 |
|---|---|
| Day 1 | 下肢力量 + 爆发 |
| Day 2 | 上肢 + 核心 + 篮球技术 |
| Day 3 | 速度 + 减速 + 变向 + 篮球 |

槽位选择规则：

1. 根据正式记录确认本周已完成槽位，不按星期机械选择。
2. 优先完成尚未完成的计划槽位。
3. 对应槽位恢复不足时延后、调整或使用低冲击替代；不因错过某天而连续补做同一主项。
4. 本周槽位全部完成时，优先技术训练、Zone 2、Mobility、Prehab 或 Recovery。

## 6. 阶段 5：分析近期刺激、恢复与趋势

### 48–72 小时刺激暴露

不仅看“练了哪个肌群”，还要统计：

- 高负荷下肢力量、单腿高负荷；
- 高冲击和中低冲击跳跃；
- 高速冲刺、高强度减速、高速变向；
- 篮球对抗和高密度篮球专项体能。

5v5、长时间 3v3 或高强度 1v1 应视为综合性的 **跳跃 + 冲刺 + 减速 + COD + Conditioning** 暴露。即使没有深蹲等力量动作，也不能据此判断下肢完全恢复。

### 恢复间隔

- 同一肌群的大重量训练至少间隔约 48 小时。
- 高冲击跳跃需检查最近的 Drop Jump、Depth Jump、高量 CMJ 和高量 Lateral Bound。
- 高速冲刺需检查 Sprint、Flying Sprint 和 Resisted Sprint。
- 减速/COD 需检查 Sprint → Stop、45°/90°/180° Cut、5-10-5 和 Reactive COD。

### 负荷与疼痛趋势

综合比较 Session RPE、训练时长、Session Load、连续训练天数、连续高冲击日、篮球对抗时间、疼痛变化和第二天反应，不得用单个固定 Session Load 数字作为是否训练的唯一依据。

疼痛需要比较晨起、训练前、热身后、训练中、训练后和第二天，判断是否持续加重、由特定动作/跳跃/变向/单腿/负重诱发、热身能否缓解、次日能否回到基线。疼痛管理优先于周期任务。

### 上次建议落实

检查上一次正式训练总结中动作降重、保持、进阶、弱点观察和疼痛跟踪建议。不得把“建议改善”当作“已经改善”；只有新的正式训练证据才能改变弱点状态。

## 7. 阶段 6：确定目标、动作模式与刺激预算

### 弱点优先级

| 优先级 | 类型 | 示例 |
|---|---|---|
| P1 | 安全与动作控制 | 落地/单腿膝控制差、减速不足、明显左右差异、疼痛相关能力问题 |
| P2 | 运动表现 | 单腿力量、起跳、加速、横向爆发或体能不足 |
| P3 | 优化项目 | 上肢力量、辅助核心能力、技能细节 |

按 `P1 > P2 > P3` 选择，但必须同时满足今日槽位、当前周期、Readiness、疼痛和刺激预算。弱点只能通过当日计划内动作或技能重点处理，不得为补弱点额外堆量，也不得为了处理 P1 而在疼痛状态下强行安排相关高冲击动作。

推荐必须明确本次处理的现存弱点及对应动作/技能；高相关弱点未纳入时，说明是因槽位、疼痛、恢复、Deload 或刺激预算限制。

### 动作模式

| 区域 | 主要模式 |
|---|---|
| 下肢 | 膝主导、髋主导、单腿、水平/垂直/横向爆发、落地、减速 |
| 上肢 | 水平推、垂直推、水平拉、垂直拉 |
| 核心 | 抗伸展、抗旋转、抗侧屈、旋转、力量传递 |
| 全身 | 携重、髋爆发、三关节伸展、全身力量传递 |

动作不能只按名称选择。同一次训练中，不因名称不同而重复堆叠相同模式；例如 Trap Bar Deadlift、RDL、Hip Thrust、Kettlebell Swing 和 Good Morning 同时出现会使髋主导/髋伸刺激过度集中。

### 全身力量传递

全身力量传递（Kinetic Chain / Total-Body Power）训练地面到手的协调传力，不能全部归为“辅助”。可从动作库选择分腿姿单臂推举、爆发推举、哑铃高拉/高翻/抓举、壶铃摆动/高翻、药球旋转抛、单侧或前架负重行走、Renegade Row 等动作。

- W1–W4：优先技术稳定、抗旋转和低复杂度力量传递。
- W5–W8：增加 Loaded Power，如 DB High Pull、Hang DB Clean、Single-Arm Push Press、KB Clean。
- W9–W12：增加动态和篮球专项力量传递，如 Step-Behind/Rotational Medicine Ball Throw、Dynamic Split-Stance Push Press。

### 动作 Level 与进退阶

| Level | 定义 |
|---|---|
| L1 | 基础动作 |
| L2 | 运动员基础 |
| L3 | 运动表现 |
| L4 | 篮球专项 / 反应 / 疲劳 / 复杂环境 |

升级必须同时满足动作稳定、无明显疼痛、技术质量良好、周期适合和刺激预算允许，不能只因为动作更高级。

动作内进阶包括加重、加次、加组、提高质量/速度或改变控制时间；一次优先只改变一个主要变量。动作间进阶沿动作库能力链进行，例如：

```text
髋爆发：RDL → Kettlebell Swing → DB High Pull → DB Clean → Single-Arm DB Snatch
抗旋转/传力：Pallof Press → Suitcase Carry → Renegade Row → 分腿姿单臂推举 → 动态分腿姿爆发推举
落地：Snap Down → Drop Landing → Single-Leg Landing → Forward Hop → Stick → Lateral Hop → Stick
减速：Step Down → 单腿跳定住 → 5m 加速急停 → 10m 冲刺急停 → Sprint → Stop → 45° Cut → Reactive COD
```

出现疼痛增加、技术/控制下降、明显疲劳、黄色 Readiness、Deload 或复杂度过高时，优先沿动作链退阶，而非直接取消整个能力。跳跃可按 `Depth Jump → Box Jump → CMJ → Snap Down` 退阶；仍不适合跳跃时只保留 Landing、Mobility 和 Prehab。

### 动作持续与替换

主力动作在技术稳定、无疼痛、RPE 正常且仍有进步时，优先持续约 6–8 次相关训练暴露。仅在疼痛、技术长期不稳、周期目标变化、已满足升级条件、器材不可用、模式严重重复或替代动作更直接服务目标时提前更换。

### 刺激预算

| 类型 | 代表项目 |
|---|---|
| 低冲击 | Mobility、基础 Prehab、Technique、Pallof Press、Dead Bug |
| 中等冲击 | Pogo、CMJ、Box Jump、基础 Acceleration、可控 Lateral Bound |
| 高冲击 | Depth/Drop Jump、高速 Sprint、Sprint → Stop、高速 90°/180° COD、Reactive COD、高频实战 |
| 高负荷力量 | Heavy Trap Bar、Heavy Squat、Heavy RDL、高负荷 Bulgarian Split Squat |

不得在一次训练中同时堆叠高强度跳跃、大量冲刺、大量高速变向、大重量下肢和长时间高强度实战。每天通常只确定 **1–2 个主要高质量目标**：Lower Power Day 可主攻 Vertical Power + Strength，COD 低量或不做；Speed/COD Day 可主攻 Acceleration + Deceleration + COD，力量仅少量维护。

## 8. 阶段 7：生成训练推荐

### 训练顺序

```text
动态热身（Dynamic Warm-up；升温 → 动态准备 → 主项预演）
→ 活动度（Mobility）
→ 防伤训练 Level 2（Prehab）
→ 落地 / 制动技术（Landing / Deceleration）
→ 速度 / 反应（Speed / Reaction）
→ 增强式 / 爆发（Plyometric / Power）
→ 主项力量（Primary Strength）
→ 单腿 / 后链 / 全身力量传递
→ 核心（Core）
→ 篮球技能 / 专项体能
→ 训练后整理与拉伸（Post-Training Cooldown & Stretching）
```

每天不要求所有主训练模块都出现，按槽位选择最少必要模块：

| 槽位 | 模块顺序 |
|---|---|
| 下肢力量 + 爆发 | Dynamic Warm-up → Mobility → Prehab → Landing → Power → Primary Strength → Single-Leg → Posterior Chain → Core → Cooldown |
| 上肢 + 篮球 | Dynamic Warm-up → Mobility → Prehab → Upper Power → Push → Pull → Shoulder Health → Core → Basketball Skill → Cooldown |
| Speed / Decel / COD | Dynamic Warm-up → Mobility → Prehab → Landing → Acceleration → Deceleration → COD → Reaction → Basketball → Cooldown |
| 下肢 B / Conditioning | Dynamic Warm-up → Mobility → Prehab → Horizontal/Lateral Power → Hip Dominant Strength → Single-Leg → Posterior Chain → Core → Basketball Conditioning → Cooldown |

一般正式训练约 **6–10 个核心训练内容**：Landing 1、Speed/Power 1–2、Primary Strength 1、Single-Leg 1、Accessory 1、Core 1、Basketball 1 个主要主题。动态热身、Mobility、Prehab 和训练后整理属于准备/恢复内容，不占 6–10 个核心训练内容名额，但仍遵循最少必要原则，不能借此无限增加动作。动作库越大不代表当天动作越多。

### 动态热身与训练后整理硬性规则

正式训练推荐中的动态热身和训练后整理必须来自动作库 P/Q 类目或其中明确引用的 A–O 既有动作，并遵循以下规则：

1. **禁止占位描述。** 不得只写“热身”“髋踝动态活动”“活动一下肩膀”“自行拉伸”“整理 5 分钟”或同类泛化内容。每个条目必须写出中文（英文）动作名、次数/距离/时长和目标区域。
2. **动态热身采用 RAMP 顺序。** 先用 1 个动作升温，再选 2–4 个与当天受力区域匹配的动态动作，最后选 1–2 个主项低强度预演；总计通常 5–10 分钟。
3. **避免重复。** 如果 P 类模板已经引用动态踝背屈、墙滑、A-Skip、低量 Pogo、Snap Down 等既有动作，不要在紧随其后的 Mobility、Prehab、Landing 或 Speed 模块重复相同剂量；合并展示并说明双重用途。
4. **不用长时间静态拉伸准备高输出。** 爆发、冲刺、变向或大重量主项之前，不安排 Q 类长时间静态拉伸作为主要热身；需要处理活动范围时优先使用动态、可控版本。
5. **训练后按实际主刺激选择。** 先轻松步行 1–3 分钟，再从 Q 类选择当天主要受力区域的 2–4 个动作，通常共 3–6 分钟；可追加 N 类 1 个呼吸动作。不得每次机械覆盖全身。
6. **不夸大拉伸效果。** 训练后拉伸用于逐步降速与活动度维护，不宣称必然消除延迟性酸痛或预防伤病。核心训练后优先选择仰卧躯干旋转与 N 类呼吸，不为“拉到腹肌/腰部”强行进入腰椎终末位。
7. **省略条件。** 正式训练默认包含具体动态热身和训练后整理；只有休息日，或红旗导致完全停止训练时可以省略，并写明原因。恢复日可以使用 N 类恢复活动替代 Q 类完整拉伸。
8. **安全优先。** 热身或拉伸出现新疼痛、麻木、关节挤压、动作范围明显下降或原症状增加时立即调整/停止；不得借热身继续测试红旗症状。

按槽位匹配：

| 今日槽位 | 动态热身覆盖 | 主项预演 | 训练后优先区域 |
|---|---|---|---|
| 下肢力量 + 爆发 | 足踝、小腿、髋屈肌、臀、腘绳肌、内收肌 | Snap Down / 低量 Pogo / 主项逐级热身组 | 小腿、股四头肌、髋屈肌、腘绳肌、臀、内收肌中选 2–4 个 |
| 上肢 + 核心 | 胸椎、胸肩、肩胛、背阔肌、手腕 | 肩胛俯卧撑 / 空杆或轻阻力推拉 | 胸肌、背阔肌、肩后侧、肱二头肌、肱三头肌、上斜方肌、前臂中选 2–4 个 |
| Speed / Decel / COD | 足踝、小腿、髋、内收肌、跑姿 | A-Skip / 渐进加速跑 / 低速侧向滑步与制动 | 下肢主要受力区域中选 2–4 个 |
| 篮球技术 / 实战 | 下肢移动链 + 胸椎、肩、手腕 | 低速运球、脚步、投篮和短距离渐进移动 | 下肢 2–3 个 + 肩/前臂 0–1 个，按实际内容选择 |
| 体能 / 恢复 | 与体能方式相同的关节和动作模式 | 从低强度逐步进入目标节奏 | 当天主要受力区域 2–3 个；恢复日可用 N 类呼吸与活动度 |

### 质量与容量

Sprint、Acceleration、Plyometric、Jump、Landing、Deceleration、COD、Reaction、Loaded Power、DB Clean、DB High Pull 和 DB Snatch 属于质量主导项目，目标是输出质量而不是制造疲劳；疲劳状态下不得安排高质量速度训练。

出现以下情况时提前停止对应模块：冲刺速度或跳跃高度明显下降、起跳节奏变慢、落地失控、膝内扣增加、左右差异变大、COD 失控、技术明显崩坏、出现新疼痛或原有疼痛明显增加。不得为完成规定组数牺牲质量。

Strength、Accessory、Core、Conditioning 和一般肌耐力可主要按 Sets / Reps / RPE 管理，但疼痛或动作质量明显恶化时仍需停止或降级。

### 黄色与红色调整

黄色状态通常减少总量约 **20%–30%**，依次优先减少高冲击跳跃、高速 COD、冲刺总量、辅助容量和主力量组数；尽量保留技术、基础力量、Mobility、Prehab 和低冲击能力训练。必须明确说明具体减少或取消了什么。

红色状态不得安排 Plyometric、Depth Jump、高强度 CMJ、Sprint、高速 Deceleration、COD、Reactive Drill、疼痛相关大重量下肢动作或高强度篮球对抗。可视情况选择 Mobility、Level 1/2 Prehab、无痛范围力量、上肢、呼吸、Recovery 或轻量 Zone 2；红旗症状按安全权限处理。

### 动作、剂量、重量与新动作

- 动作只能来自动作库；组数、次数、时长、距离、RPE 和负荷必须来自 12 周计划、动作库、用户历史或用户本次明确输入。
- 重量只能来自 12 周计划规定、动作库规则、用户历史或用户本次明确提供。
- 没有历史重量依据时不提供具体公斤数，改用 RPE 6、轻重量试做、保留 3–4 RIR 或技术优先。
- 用户从未训练过的动作必须标记 **“新动作”**，采用较低复杂度、轻重量、少次数、技术优先，且不与高疲劳堆叠；DB Clean、DB Snatch、Explosive Push Press、Depth Jump 和 Reactive COD 尤其如此。

### Dashboard 与正式记录边界

Dashboard 是只读展示层，不添加完成勾选、数量输入或“完成今日训练”逻辑。推荐阶段不得：

- 增加训练天数或 Session Load；
- 写入已完成动作、预计 Session RPE、预计疼痛或正式训练历史；

## 10. 完成前检查

- 五项输入不完整时，没有正式计算 Readiness 或生成正式计划。
- 红旗和疼痛没有被高 Readiness、周计划或弱点目标覆盖。

- 动作存在于动作库，剂量和重量有明确依据；新动作已标记并降复杂度。
- 正式训练包含按槽位匹配的具体动态热身与训练后整理动作；没有泛化占位语，也没有在高输出主项前安排长时间静态拉伸。
- 动态热身没有与后续 Mobility、Prehab 或主项预演重复堆叠；训练后只选择当天主要受力区域。
- 48–72 小时刺激、恢复间隔、疼痛趋势、弱点、动作模式和刺激预算均已进入决策。
- 训练只保留必要动作，质量项目附有针对性的 Quality Stop。
- 输出、月度 Readiness 和 Dashboard 展示一致。
- 推荐没有进入正式训练统计，也没有使用旧 `localStorage` 或 `train1.0` 数据。
- 所有建议均为训练负荷管理，不表述为疾病诊断或治疗方案。
