# recommend-training-2

为 `train2.0` 生成今日训练建议。所有结论必须可追溯到用户输入、月度训练记录或 2.0 训练文档，不得凭空补充训练数据。

## 适用请求

用户表达以下意图时使用：

- “推荐今天训练什么”
- “今天该怎么练”
- “根据我的状态安排训练”
- “更新 Readiness”

本技能只负责采集并记录当日 Readiness、分析和推荐训练，不把尚未完成的推荐写成正式训练记录。训练结束后由 `record-training-2` 记录实际完成内容。

## 固定配置

- 12 周周期开始日期：`2026-09-21`
- 默认计划：`train2.0/12周计划安排.md` 的 3 日版
- 正式训练记录唯一事实源：`train2.0/records/YYYY-MM.md`
- 月度 HTML 与 `train2.0/dashboard.html` 是同步展示层
- 不读取或迁移旧 `localStorage` 中的 Readiness、Session 或训练历史
- 不自动读取或改写 `train1.0/` 数据

## Step 1：确认日期和 Readiness 输入

先确认训练日期，再收集以下五项：

| 指标 | 范围 | 方向 |
|------|------|------|
| 睡眠 | 1–5 | 越高越好 |
| 当前疲劳 | 1–5 | 越低越好 |
| 当前酸痛 | 1–5 | 越低越好 |
| 当前疼痛 | 0–10 | 越低越好 |
| 当前训练意愿 | 1–5 | 越高越好 |

规则：

1. 只使用用户明确提供的数据，不自行打分。
2. 日期不明确，或用户所说“今天”与当前日期存在歧义时，先确认日期。
3. 缺少输入时一次最多询问 2–3 项；收到回答后再询问剩余项。
4. 五项未齐全时不得计算分数或输出正式推荐。
5. 超出范围的值必须请用户重新确认，不能自动截断。
6. 疼痛不只记录数字；疼痛大于 0 时，询问部位和性质。若出现尖锐痛、肿胀、卡顿、不稳、跛行或持续加重，记录为红旗症状。

## Step 2：计算 Readiness

使用以下等权、可解释公式：

```text
Readiness = round(20 × (
  睡眠 / 5
  + (6 - 疲劳) / 5
  + (6 - 酸痛) / 5
  + (10 - 疼痛) / 10
  + 训练意愿 / 5
))
```

结果范围为 0–100。分级必须同时应用疼痛覆盖规则：

| 等级 | 条件 | 训练权限 |
|------|------|----------|
| 绿色 | 分数 ≥75 且疼痛 ≤2，且无红旗症状 | 可执行计划训练，再结合近期负荷调整 |
| 黄色 | 分数 60–74，或疼痛 3–4，且无红旗症状 | 总量减少约 20%–30%，优先技术、低冲击与可控强度 |
| 红色 | 分数 <60，或疼痛 ≥5，或存在红旗症状 | 取消跳跃、冲刺、高速变向和疼痛相关负重；仅建议恢复或合适的 Prehab |

疼痛限制始终优先于总分。分级是训练负荷管理，不是医学诊断。存在红旗症状或疼痛持续加重时，应建议停止相关训练并寻求医疗或康复专业人员评估。

## Step 3：读取必需数据源

推荐前必须读取全部来源，缺少任一来源时说明缺失并停止正式推荐：

1. `train2.0/篮球运动训练理念.md`
   - 能力模型、动作排序和训练原则。
2. `train2.0/训练周期安排建议.md`
   - 大周期、中周期、周微周期和负荷调整规则。
3. `train2.0/12周计划安排.md`
   - 当前周次、阶段目标、3 日版当日槽位、组次和 Deload 规则。
4. `train2.0/篮球运动员版动作库 2.0.md`
   - 动作名称、能力分类、等级、冲击、器材、描述和进退阶依据。
5. `train2.0/records/` 中覆盖训练日前最近 3 个训练周的月度 Markdown。
   - 实际训练日期、动作、组次、负荷、Session RPE、Session Load、疼痛、Readiness、总结和弱点。
6. `train2.0/dashboard.html`
   - 当前展示结构和需要同步的 Readiness 位置；不得把页面内旧 localStorage 历史作为分析依据。

若训练记录不足 3 周，使用现有全部记录并明确标注“历史记录不足 3 周”。不得用 1.0 数据补足。

## Step 4：确定周期位置和计划槽位

1. 以 `2026-09-21` 为周期第 1 周第 1 天，按连续 7 天计算当前周次。
2. 日期早于周期开始日或晚于第 12 周时，先向用户确认是否继续沿用该周期，不能擅自循环周次。
3. 从 `12周计划安排.md` 确认当前中周期和周目标，例如进入、增量、高刺激或 Deload/测试。
4. 按 3 日版查找本周尚未完成的训练槽位；不能只按星期机械选择。
5. 若本周计划槽位已经完成，结合恢复状态决定补缺、技术训练或恢复，不重复堆叠同一主项。

## Step 5：分析近期训练和恢复

逐项输出分析依据：

1. **训练频率**：最近 3 周各能力板块和主要肌群的实际频率。
2. **恢复间隔**：同一肌群的大重量训练至少间隔 48 小时；检查上一次跳跃、冲刺、变向和高负荷下肢训练。
3. **负荷趋势**：比较 Session Load、Session RPE、训练时长和连续高负荷日；不自行设定用户不存在的绝对负荷阈值。
4. **疼痛趋势**：比较训练前后与次日疼痛，确认是否与特定动作或冲击类型相关。
5. **动作渐进**：同一动作优先保持 6–8 次训练后再进阶；单次只选择加重、加次、加组或控速中的一种。
6. **弱点与未解决问题**：只采纳记录中客观存在的动作质量问题、左右差异、测试短板或用户明确反馈。
7. **上次建议落实情况**：检查上次训练总结中的调整是否已执行，不把未验证的改善视为完成。

## Step 6：生成推荐

推荐必须按以下优先级决策：

1. 红旗症状和疼痛权限。
2. 当日 Readiness 分级。
3. 当前周期周次与 Deload/测试要求。
4. 本周尚未完成的 3 日版槽位。
5. 最近训练、Session Load 与至少 48 小时恢复间隔。
6. 待改善弱点和动作质量。
7. 动作库中的等级、冲击、器材和进退阶条件。

训练顺序遵循：

```text
热身与 Level 2 防伤 → 爆发/速度 → 主项力量 → 辅助 → 核心 → 拉伸
```

动作和剂量规则：

- 只推荐 2.0 文档中存在的动作。
- 组次、次数、时长和负荷必须来自 12 周计划、动作库或用户历史。
- 历史中没有重量依据时，不给出具体公斤数；使用 RPE、轻重量试做或动作库已有起始规则。
- 用户从未做过的动作标注“新动作，从轻重量开始试”。
- 黄色状态按计划总量减少约 20%–30%，明确写出减少了哪一项。
- 红色状态不得为了凑齐计划而安排高冲击动作。
- 爆发和速度项目放在疲劳前，但疼痛规则可取消这些项目。
- 推荐保持最少必要动作，不额外添加与周期目标无关的内容。

## Step 7：同步每日 Readiness

得到用户确认的五项输入后，更新以下展示数据：

1. `train2.0/records/YYYY-MM.md` 对应日期的 Readiness 条目。
2. 若月度 HTML 已存在，同步 `train2.0/records/YYYY-MM.html`。
3. 同步 `train2.0/dashboard.html` 的每日 Readiness 展示。

同步约束：

- 三处五项原始值、得分、等级、疼痛部位和备注必须一致。
- 若对应日期尚无正式训练，可只记录 Readiness，不创建虚假的已完成训练。
- 同一天重新评估时更新当日条目，并保留必要的时间或变更备注；不得累计为多个训练日。
- 若当月记录文件尚未建立，明确告知需要先按 `record-training-2` 的月度模板初始化；在模板完成前不要临时发明另一种文件结构。

## Step 8：同步 Dashboard 今日推荐

推荐生成后，必须把同一份推荐同步到 `train2.0/dashboard.html`，使 Dashboard 成为当日推荐的只读展示层，而不是训练完成记录入口。

### 必须同步的三部分

1. **今日训练推荐**
   - 更新当前日期、周期周次、训练模式和当日槽位对应的推荐结构（默认 3 日版，对应 `PLAN3` 和当前周期槽位）。
   - 按推荐顺序写入热身、Level 2 防伤、爆发/速度、主项力量、辅助、核心和整理/拉伸等模块。
   - 每个模块同步动作名称、组数、次数、距离、时长、RPE 或“按计划”等剂量信息；不得只更新模块标题而保留旧动作或旧剂量。
   - Dashboard 仅展示推荐，不添加完成勾选、数量输入或“完成今日训练”逻辑；实际完成情况、时长、Session RPE、疼痛和 Session Load 由 `/record-training-2` 记录。

2. **为什么今天这样练？**
   - 将推荐输出中的周期目标、Readiness 权限、近期训练/恢复间隔、疼痛限制、弱点或动作进阶依据，压缩为 Dashboard 的 `todayReason` 展示内容。
   - 推荐被 Readiness 调整或取消的项目必须在此处明确说明，不能让 Dashboard 看起来仍是完整高负荷计划。
   - 保留“训练后请使用 `/record-training-2` 记录实际完成内容、Session RPE 和疼痛”的提示。

3. **今日技能**
   - 将本次推荐直接训练的篮球能力写入 Dashboard 的 `todaySkills`，例如运球、投篮、终结、防守/脚步；技能说明必须与推荐内容一致。
   - 不得把未出现在推荐中的能力写成今日重点，也不得因推荐调整而保留已经取消的技能重点。

### 同步规则

- Dashboard 当日推荐必须与命令最终输出的日期、周期位置、训练模式、槽位、动作、剂量、Readiness 调整、推荐依据和今日技能一致。
- 同日重新评估或重新推荐时，覆盖 Dashboard 对应日期/槽位的旧推荐，不能拼接重复模块或残留上一版的 `todayReason`、`todaySkills`。
- 只更新推荐展示结构和 Readiness 展示数据；不得把推荐动作、预计组次、预计时长或预计 Session Load 写入 `FORMAL_RECORDS`、月度训练天数或 Session Load 统计。
- 不读取旧 `localStorage` 生成或补齐 Dashboard 推荐，不把旧缓存中的训练内容当作正式历史。
- 如果 Dashboard 缺少对应的推荐结构、`todayReason` 或 `todaySkills` 挂载点，报告未同步项并停止，不得临时创造与现有页面不兼容的数据结构。
- 完成同步后核对：浏览器刷新后显示正确的当日槽位；推荐区无手动完成控件；“为什么今天这样练？”和“今日技能”与命令输出一致；正式训练天数和 Session Load 未因推荐而增加。


```markdown
## 今日 Readiness

- 日期：YYYY-MM-DD
- 睡眠：N/5
- 疲劳：N/5
- 酸痛：N/5
- 疼痛：N/10（部位与性质）
- 训练意愿：N/5
- Readiness：N/100（绿色/黄色/红色）
- 训练权限：具体限制

## 周期定位

- 周期：第 N 周 / 阶段名称
- 本周已完成：基于记录列出
- 今日计划槽位：名称

## 今日训练推荐

按“热身与防伤、爆发/速度、主项力量、辅助、核心、拉伸”列出动作、组次和强度；被 Readiness 调整或取消的内容要明确说明。该部分必须同步到 `train2.0/dashboard.html` 的今日推荐展示。

## 为什么今天这样练？

用简洁条目说明周期目标、Readiness 权限、近期训练与恢复间隔、疼痛限制、弱点和动作进阶依据；必须同步到 Dashboard 的 `todayReason`。

## 今日技能

列出本次推荐实际训练的篮球能力及对应重点，例如运球、投篮、终结、防守/脚步；必须同步到 Dashboard 的 `todaySkills`，并与推荐内容一致。

## 推荐依据

1. 当前周期与周目标
2. 最近 3 周频率和恢复间隔
3. Session Load 与疼痛趋势
4. 弱点及上次问题
5. 动作库匹配与本次渐进方式

## 训练后需要记录

列出训练结束后应提供给 `record-training-2` 的最少信息。
```

## 禁止行为

1. 禁止编造 Readiness、疼痛、动作表现、训练负荷、组次或重量。
2. 禁止仅凭 Readiness 总分忽略疼痛或红旗症状。
3. 禁止把推荐计划写成已经完成的训练。
4. 禁止从旧 `localStorage` 或 `train1.0/` 推断 2.0 历史。
5. 禁止推荐 2.0 文档中不存在的动作，或为缺少描述的动作生成虚构说明。
6. 禁止在没有最近训练与周期分析的情况下只按星期返回固定模板。
7. 禁止把训练建议表述为疾病诊断或治疗方案。
