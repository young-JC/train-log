# training-video-plan

在一次 `train2.0` 训练完成并正式记录后，把训练数据转化为一条有事实依据、有冲突或认知价值、可直接照着剪辑的短视频方案。

本技能解决的是“这次训练最值得讲什么、怎样讲、怎样剪”，不是重新推荐训练，也不是把整份训练记录机械地念一遍。

## 适用请求

用户表达以下意图时使用：

- “根据今天的训练帮我做短视频方案”
- “这次训练怎么剪”
- “生成本次训练的旁白和分镜”
- “给我一个抖音剪辑脚本”
- “从最新训练记录里找一个视频选题”
- “把这次训练做成系列下一集”

默认处理 `train2.0`。用户没有明确要求时，不读取或混用 `train1.0`。

## 职责边界

本技能负责：

1. 从正式训练记录中提取本次可传播的事实；
2. 选择一个最有价值的核心叙事，而非平均介绍全部动作；
3. 生成适合短视频的开头钩子、故事结构、完整旁白和逐秒分镜；
4. 标明每个镜头需要的素材、画面重点、字幕、音效和转场；
5. 为缺失素材提供不造假的替代画面；
6. 给出封面、标题、发布文案、置顶评论和下一期衔接；
7. 保持长期连载的统一定位，同时避免每期都剪成相同流水账。

本技能不负责：

- 修改正式训练记录、能力评估、弱点追踪或 Dashboard；
- 把计划、推荐动作写成已经完成的训练；
- 编造动作表现、疼痛、心理感受、现场事件或训练效果；
- 代替医学诊断、康复建议或专业教练现场判断；
- 在用户未提供已发布内容时，声称某一主题此前已经或尚未发布。

除非用户明确要求保存脚本，否则只输出方案，不创建视频脚本文档，也不修改任何训练数据文件。

## 1. 默认创作定位

用户未另行指定时，采用以下默认值：

| 项目 | 默认值 |
|---|---|
| 平台 | 抖音 |
| 比例 | 9:16 竖屏 |
| 分辨率 | 1080 × 1920 |
| 时长 | 45–60 秒 |
| 表达方式 | 第一人称真实训练记录 + 篮球训练认知 |
| 旁白 | 中文本人旁白，口语化，不使用宣传片腔调 |
| 核心受众 | 没有系统训练经验、进入健身房后容易照搬三分化或短视频动作的篮球爱好者 |
| 系列定位 | 普通篮球爱好者，用 AI 辅助完成 12 周系统训练实验 |
| AI 定位 | 整理训练原则、个人状态和历史记录的辅助工具，不是替代训练者判断的“万能教练” |
| 单集目标 | 让观众记住一个问题、一次决策或一个结果，而不是看完一份训练清单 |

如果用户指定平台、横竖屏、时长、是否露脸、是否使用旁白或内容风格，以用户要求为准。

### 时长选择

不要机械地每次都输出 60 秒：

- 单一动作或单一认知：30–45 秒；
- 标准训练故事：45–60 秒；
- 明确冲突、阶段复盘或测试：60–75 秒；
- 数据和素材不足时宁可做 25–40 秒，也不要用空话拉长。

## 2. 确认训练日期与记录状态

### 日期规则

1. 用户明确给出日期时，使用该日期，并检查日期对应的正式记录。
2. 用户说“今天”“昨天”等相对日期时，转换成绝对日期并在输出中写明。
3. 用户没有给日期时，读取 `train2.0/records/`，选择不晚于当前日期的最新一条“已完成”或“部分完成”训练，并明确说明选择了哪一天。
4. 同一天有多个训练段时，先判断它们是否共同构成一个故事；若主题明显不同，选择传播价值最高的一段，并把另一段列为备选选题，不强行混剪。
5. 若同日记录被更新，以最新正式记录为准，不重复生成虚构的第二次训练。

### 记录门槛

正式训练视频方案至少需要：

- 一个明确已完成、部分完成或明确取消的训练事件；
- 至少一个可确认的动作、项目、决策或训练结果；
- 能够支撑核心叙事的正式记录或用户明确补充。

若当天只有 Readiness 而没有完成训练：

- 不得生成“本次训练回顾”；
- 如果记录明确说明训练为何取消或改为休息，可以生成“为什么今天没有训练”的决策型内容；
- 如果连取消原因也没有记录，说明证据不足，并建议先使用 `record-training-2` 补充事实。

若记录尚未正式写入，优先提示先使用 `record-training-2`；不得从推荐计划反推实际完成情况。

## 3. 必读数据与事实优先级

### 必读来源

生成正式方案前，按需要读取：

1. `train2.0/records/YYYY-MM.md` 中目标日期的完整训练详情；
2. `train2.0/records/` 中最近 3 个训练周的 Markdown，用于寻找同动作、同槽位或同问题的可比历史；
3. `train2.0/12周计划安排.md`，用于确认周次、阶段与本次槽位目标；
4. `train2.0/篮球运动训练理念.md`，用于解释动作排序和训练原则；
5. 当前动作事实源 `train2.0/篮球运动员版动作库 3.0.md`；若仓库后续明确更换动作库版本，以项目当前指定版本为准；
6. `train2.0/weakness-tracking.md`，用于确认本次是否有既有弱点的新证据；
7. `train2.0/ability-assessment.md`，用于确认本次是否建立基线或刷新可比较最佳结果；
8. 与目标日期明确绑定的当日推荐内容，用于比较“原计划与实际执行”；如果只能找到当前日期推荐而目标是历史日期，不得误用。

### 可选上下文

用户提供时一并使用：

- 已拍摄素材清单及每段大致内容；
- 失败组、临场反应、自述、进出健身房等现场镜头；
- 希望控制的成片时长；
- 是否露脸、是否本人配音；
- 最近已经发布的 3–5 个视频主题及表现；
- 希望突出知识、故事、数据、动作或个人感受中的哪一类。

除非缺少这些信息会使方案无法执行，否则不要阻塞生成。使用默认值，并把素材假设和替代方案写清楚。

### 事实优先级

发生冲突时按以下顺序使用：

```text
正式月度训练记录中的实际完成数据
→ 用户本次明确补充的现场事实
→ 能力评估与弱点追踪中的正式数据
→ 与目标日期绑定的训练推荐
→ 12 周计划与训练理念
→ 动作库的一般说明
```

计划、动作库和一般训练原则只能解释“为什么可能这样安排”，不能证明用户实际完成、动作质量良好或已经获得效果。

## 4. 建立本次“事实卡”

先在内部整理以下信息，最终输出“事实依据”摘要供用户核对：

### 基本事实

- 日期；
- 第几周、阶段、槽位；
- 训练状态：已完成、部分完成、调整、取消或恢复；
- Readiness 原始值、得分与权限；
- 训练前、中、后疼痛及部位；
- 总时长、Session RPE、Session Load；
- 实际动作顺序、组次、负荷、RPE 和反馈；
- 删减、替换、临时增加或提前停止的内容。

### 可比较事实

只在口径一致时比较：

- 与上一次同动作相比的负荷、完成量、RPE 或质量评分；
- 是否为首次有效结果；
- 是否严格优于能力评估中的当前最佳；
- 同类训练间隔；
- 本次 Session Load 与近期记录的客观差异；
- 弱点是否出现新证据或明确改善证据。

不得把以下内容包装成进步：

- 动作或变式不同；
- 器材、侧别、单位或测试条件不同；
- 重量上升但次数下降，且没有正式比较规则；
- 主观感觉缺失；
- 只有计划剂量，没有实际结果；
- 一次无疼痛就宣称伤病解决；
- Readiness 高就宣称身体处于最佳状态。

### 故事元素

从事实中寻找：

- **问题**：本次要解决什么；
- **冲突**：计划与状态、疼痛、器材、时间或实际表现有什么矛盾；
- **决策**：因此保留、删减、替换或调整了什么；
- **证据**：哪一组数据或哪一个动作能证明；
- **结果**：最终完成了什么；
- **未决问题**：下一次还要观察什么。

没有记录支持的故事元素必须标记“没有证据”，不能为了戏剧性补写。

## 5. 选择唯一核心叙事

一条视频只设一个主命题。其余动作只是证据或背景。

### 选题优先级

依次检查：

1. **真实冲突或临场调整**  
   例如疼痛限制、Readiness 与计划冲突、器材不可用、时间不足、动作质量下降、推荐没有照搬。
2. **明确可比较的变化或结果**  
   例如建立首次基线、刷新最佳、相同负荷下 RPE 降低、计划完成度变化。
3. **能纠正常见误区的动作选择**  
   例如为什么篮球爱好者仍练卧推、为什么爆发先于力量、为什么不追求每次力竭。
4. **既有弱点的新证据**  
   例如左右差异、落地控制、减速、单腿稳定或肩部健康；只使用正式记录中的证据。
5. **阶段推进或训练闭环**  
   例如从进入周到增量周、Deload、测试周、推荐—执行—记录—调整。
6. **完整训练日**  
   只有前五类都没有足够材料时，才以“今天怎样系统地完成某一主题”为主线。

### 选题判断标准

为最多 3 个候选角度做简短比较：

| 维度 | 判断问题 |
|---|---|
| 受众相关性 | 普通篮球爱好者会遇到吗？ |
| 事实强度 | 是否有明确记录、数据或实际决策支撑？ |
| 反差/悬念 | 是否存在“原本以为……实际却……”？ |
| 视觉可表达性 | 是否能用训练镜头、局部数据或前后对比证明？ |
| 系列价值 | 是否推进 12 周实验，而不是孤立动作展示？ |
| 素材可行性 | 当前可能拥有的素材能否完成；缺少时是否可合理替代？ |

选定一个主角度，并用一句话说明为什么它比另外两个更适合本次。备选角度放在输出末尾，不能与主片混在一起。

### 核心句公式

先写出一条内部核心句：

```text
这条视频要让【目标观众】通过【本次真实证据】明白【一个具体观点】，并对【下一次验证/调整】产生期待。
```

如果一句话中出现两个以上“以及”，说明主题通常过多，应继续收窄。

## 6. 叙事类型轮换

根据本次事实选择一种主类型：

### A. 冲突调整型

```text
原计划 → 现场问题 → 判断依据 → 调整 → 结果 → 后续观察
```

适用于疼痛、疲劳、器材、时间、动作质量或计划不适配。

### B. 动作选择型

```text
常见疑问 → 为什么选这个动作 → 它在本阶段的角色 → 实际完成 → 是否保留/进阶
```

重点解释“为什么进入本次计划”，不要做脱离个人阶段的万能动作教学。

### C. 数据变化型

```text
结果先行 → 上一次数据 → 本次可比数据 → 变化意味着什么 → 下一步只改一个变量
```

只使用严格可比较的数据，不把普通波动夸张成显著提升。

### D. 阶段复盘型

```text
阶段目标 → 实际完成 → 有变化的指标 → 没变化或暴露的问题 → 下一阶段调整
```

适用于每周简报、W4/W8/W12、Deload 或正式测试。

### E. 训练认知型

```text
以前的误区 → 本次训练原则 → 2–3 个动作证据 → 实际反馈 → 一句话结论
```

适合“从乱练到知道为什么练”的账号主线。

### F. 完整训练日型

```text
今日状态 → 训练目标 → 准备 → 2–3 个关键动作 → 记录结果 → 下一步
```

不逐个报菜单；非核心动作使用蒙太奇快速带过。

若用户提供近期已发布主题，优先避免连续 3 条使用同一叙事类型。没有发布历史时，不假装知道此前用过什么类型。

## 7. 开头钩子规则

必须提供 3 个有事实依据的钩子，并选定其中 1 个用于正式分镜：

1. 痛点型；
2. 冲突/反常识型；
3. 结果/悬念型。

### 钩子要求

- 核心信息在前 2 秒内出现；
- 第一句通常控制在 10–22 个汉字；
- 不从“大家好”“今天带大家看”“这是我第几次训练”开始；
- 不先播放 Logo、固定片头或完整 Dashboard；
- 不使用记录无法兑现的结果承诺；
- 不使用“震惊”“废了”“逆天”等与事实不符的夸张词；
- 第一个画面优先使用人物、关键动作、失败/调整瞬间或醒目的单条数据；
- Dashboard 只能作为证据，不应成为长时间开场主体。

### 推荐句式

```text
我原本以为……，但今天的记录告诉我……
AI今天建议我……，但我没有直接照做。
同样的重量，这次为什么没有继续加？
篮球爱好者练这个动作，重点可能根本不是……
状态分数很高，为什么我还是删掉了……？
训练了 N 周，真正先变化的不是……
```

只能填入本次正式记录支持的内容。

## 8. 分镜与旁白生成规则

### 标准节奏

根据主题调整，但默认参考：

```text
0:00–0:02  钩子：问题、冲突或结果
0:02–0:08  最少必要背景
0:08–0:15  今天的决策和依据
0:15–0:40  2–3 个关键训练证据
0:40–0:52  实际结果、记录或对比
0:52–0:60  下一步调整或未决问题
```

### 镜头节奏

- 前 3 秒：0.5–1.2 秒一个视觉变化；
- 前 10 秒：单镜头通常不超过 2 秒；
- 主体动作：每个有效片段通常 1.5–3 秒；
- 关键失败、最后一组或动作细节可以保留 3–4 秒；
- Dashboard 或记录页单次通常 0.8–1.5 秒，只放大一项数据；
- 不连续展示 5 秒以上的小字页面；
- 转场优先硬切、动作匹配切、推近和遮挡切，不堆砌花哨模板；
- 每 5–8 秒至少发生一次信息变化：问题、镜头、数据、动作意义或结果。

### 旁白规则

1. 使用第一人称和真实口语：如“我今天……”“我原本……”“这次记录里……”；
2. 画面已经说明“做了什么”时，旁白解释“为什么、发生了什么、下一步怎样”；
3. 动作名称、组次和重量可由屏幕数据卡承担，旁白不必全部朗读；
4. 每句话尽量只表达一个意思；
5. 使用短句和自然停顿，不写论文式长句；
6. 不把 AI 说成拥有身体感受或绝对判断能力；
7. 不使用“科学证明我一定会提高”等过度结论；
8. 疼痛只陈述记录和采取的调整，不推断病因；
9. 没有结果时可以说“还需要继续观察”，不强行正向总结；
10. 结尾要从本次结果自然产生下一步，不机械地只说“记得关注”。

### 字数校验

按约 3.5–4.2 个汉字/秒的自然语速估算，并为呼吸和原声留出时间：

- 30 秒：约 90–115 个汉字；
- 45 秒：约 140–175 个汉字；
- 60 秒：约 190–230 个汉字；
- 75 秒：约 235–285 个汉字。

完整旁白超过对应范围时，优先删除动作清单、重复结论和抽象口号，而不是让配音加速。

### 画面不能证明时

- 没有动作镜头：使用同动作其他组、器材特写、训练记录局部、进出健身房或本人补录口述，并明确字幕为“本次记录”；
- 没有失败瞬间：不得使用另一次训练假装本次失败，可用文字和本次记录说明；
- 没有前后对比画面：使用同口径数据卡，不用不相关旧素材制造假对比；
- 没有 Dashboard 录屏：使用简洁自制数据卡，不要求展示整页；
- 没有本人出镜：用动作 B-roll、手部记录、器材和环境镜头承担画面；
- 完全没有训练素材：输出“记录复盘型”方案，并明确需要补拍口述、训练包、鞋、器材或屏幕录制等非伪造镜头。

## 9. 字幕与视觉规则

### 主字幕

- 使用烧录字幕，确保静音观看也能理解；
- 一行通常不超过 12–15 个汉字，同屏最多两行主字幕；
- 与旁白逐句同步，不把整段文字一次铺满；
- 关键词使用固定强调色，普通字幕保持高对比；
- 字幕避开抖音右侧交互区、底部标题区和人物脸部；
- 不把 Dashboard 中的小字直接缩小后当字幕。

### 信息卡

每张卡只表达一类信息：

```text
今日主题：上肢力量 + 核心稳定
实际完成：14 kg · 3×7 · RPE 6
疼痛：训练前 0/10 → 训练后 0/10
本次调整：取消高冲击跳跃
周期：W2 · 增量周 · D2
```

只展示正式记录中存在的字段。

### Dashboard 使用

- 先裁掉浏览器、无关模块和空白；
- 每次只放大一个重点，例如 Readiness、今日槽位、某个动作结果或 Session Load；
- 使用框线、遮罩或轻微推近引导视线；
- 完整 Dashboard 可在 0.5–1 秒内作为系统感建立镜头，但不能让观众自行找重点；
- 训练动作应是主体，Dashboard 是证据层。

### 系列识别

保留固定但不抢钩子的视觉元素：

```text
12周篮球训练实验
W{周次} · 第{本周期已完成训练序号}次训练
```

只有能从正式记录准确计算序号时才显示“第 N 次”；否则只显示周次和日期。

固定片头不得占据前 2 秒。系列角标可在钩子后出现 1 秒或常驻小角落。

## 10. 音频与剪辑细节

### 声音层级

1. 人声旁白最清晰；
2. 关键动作原声，如哑铃落位、鞋底摩擦、呼吸、球声，短暂抬高；
3. BGM 只承担节奏与情绪，不盖住人声；
4. 数据卡、转折和结果可用轻微提示音，不要每次切镜都加音效。

### BGM 建议

只推荐风格、速度和进入位置，不凭空指定“当前热门音乐”：

- 理性复盘：低饱和电子、轻鼓点、80–100 BPM；
- 训练推进：节奏清晰的 Hip-hop / Electronic、95–120 BPM；
- 冲突调整：开头低频简洁，决策后进入鼓点；
- 阶段总结：前半克制，结果段稍有抬升。

具体曲目如需跟随平台趋势，应让用户在发布当天从可商用或平台授权音乐中选择。

### 原声停顿点

正式分镜至少安排 1–2 处 0.3–1 秒的原声空间，例如：

- 关键一组开始前；
- 最后一次动作完成；
- 器械落位；
- 篮球入网；
- 训练结束后的呼吸或收拾装备。

这样可以减少“全程宣传片旁白”的感觉。

## 11. 固定输出格式

每次正式调用按以下顺序输出。用户要求精简时可以压缩，但不得省略事实边界、主分镜和完整旁白。

# 本次短视频剪辑方案

## 1. 一句话结论

- **建议主线**：
- **叙事类型**：A–F 中的一种
- **目标观众**：
- **建议时长**：
- **观众看完只需记住**：
- **为什么选它**：说明它相对另外候选角度的优势

## 2. 事实依据

列出 4–8 条本次方案实际引用的记录：

- 日期、周期、槽位；
- 关键动作与结果；
- Readiness、疼痛、时长、RPE、Session Load 中与故事有关的项；
- 与上次可比数据；
- 本次调整、弱点证据或能力评估变化。

没有用于叙事的数据不必罗列。明确区分：

- **正式记录**；
- **用户补充**；
- **合理创作建议但不是事实**，例如建议补拍哪个镜头。

## 3. 备选角度比较

用简表给出最多 3 个候选：

| 角度 | 核心冲突/价值 | 事实强度 | 素材要求 | 结论 |
|---|---|---|---|---|

标明最终采用哪一个。不要把多个候选拼成一条视频。

## 4. 开头钩子

提供三版：

- **痛点型**：
- **冲突/反常识型**：
- **结果/悬念型**：
- **本次采用**：说明选择原因

同时写出第一帧画面和第一屏大字。

## 5. 素材清单

分成四组：

### 必须使用

只列完成主线所必需的 4–8 个镜头，并标注建议时长和构图。

### 有则加分

例如失败组、训练后表情、环境、鞋、器械、球、计时器、本人对镜口述。

### 屏幕素材

精确指出需要录制或截取哪个页面、哪个字段、怎样裁切和高亮。

### 不建议使用

指出本次应舍弃的重复动作、长页面、小字、与主线无关的数据或无意义过场。

如果不知道用户实际拍到了什么，明确写“以下为所需素材，不代表已经存在”，并在后文逐项提供替代。

## 6. 逐秒分镜表

必须使用下列表头：

| 时间码 | 时长 | 画面与景别 | 旁白/原声 | 屏幕文字 | 剪辑与声音 | 素材来源/缺失替代 |
|---|---:|---|---|---|---|---|

要求：

- 时间码总和与建议时长一致；
- 每一段旁白能在对应时长内自然读完；
- 写明动作镜头使用全景、中景、特写还是局部慢放；
- 写明是硬切、动作匹配切、轻推近还是原声停顿；
- 标明 Dashboard 应裁切到哪个数据；
- 缺失替代不得假装是本次真实训练。

## 7. 完整旁白稿

输出一版可以直接复制录音的连续文稿：

- 使用 `[停顿]`、`[强调]` 标记语气，但标记不计入朗读；
- 给出预计字数和预计自然语速时长；
- 与逐秒分镜中的旁白逐句一致；
- 不在完整稿中加入镜头说明；
- 若保留原声，使用 `[原声 0.5 秒]` 标记位置。

## 8. 屏幕文字包

至少包括：

- **封面文案**：3 版，每版优先 8–14 个汉字；
- **系列角标**：1 版；
- **第一屏大字**：1 版；
- **关键数据卡**：按出现顺序列出；
- **动作解释卡**：每个只写一个作用；
- **结尾悬念**：1 版。

避免封面同时堆叠“AI、系统化、篮球、训练、计划、记录、分析”等全部关键词。

## 9. 剪辑执行参数

给出本次具体建议：

- 画幅与安全区；
- 开头切镜频率；
- 主体段平均镜头长度；
- 哪一处使用慢放，慢放比例建议；
- 哪一处保留动作原声；
- BGM 风格和开始抬升位置；
- 字幕重点色；
- Dashboard 的裁切和动效；
- 不应该使用的转场或特效；
- 导出建议：1080 × 1920、H.264，并保持原始素材可支持的帧率，不虚构升帧。

## 10. 缺失素材替代方案

用表格逐项给出：

| 缺失素材 | 首选替代 | 次选替代 | 不能怎样替代 |
|---|---|---|---|

例如不能拿另一天的失败镜头冒充本次，不能拿推荐页面冒充完成结果。

## 11. 发布包装

- **标题**：3 版，分别偏痛点、冲突、系列记录；
- **发布正文**：1 版，2–4 句，不重复整段旁白；
- **话题**：3–5 个高度相关标签，不堆无关热词；
- **置顶评论**：1 条，提出与本期核心相关的具体问题；
- **评论区引导**：预判 2–3 个观众可能提出的问题，并给出基于事实的简短回复方向。

## 12. 系列衔接

- 本期在 12 周主线中的位置；
- 本次留下的未决问题；
- 下一期最自然的选题；
- 下次训练需要额外拍摄的 3–5 个镜头；
- 如果本期不适合接完整训练，建议改接动作解释、数据复盘或冲突调整。

## 13. 发布前检查

列出可勾选清单：

- [ ] 前 2 秒出现具体问题、冲突或结果；
- [ ] 一条视频只有一个主命题；
- [ ] 所有数值与正式记录一致；
- [ ] 推荐和计划没有被说成实际完成；
- [ ] 没有把普通波动包装成进步；
- [ ] 没有对疼痛做医学诊断；
- [ ] 旁白没有逐项念动作菜单；
- [ ] Dashboard 每次只突出一个重点；
- [ ] 手机静音观看也能理解；
- [ ] 结尾留下由本次事实产生的下一步；
- [ ] 画面中没有泄露不希望公开的个人信息；
- [ ] 使用的音乐、字体和素材具备发布权限。

## 12. 长期连载规则

### 固定的内容

长期保持：

- “普通篮球爱好者的 12 周系统训练实验”这一核心承诺；
- “问题 → 决策 → 执行证据 → 结果 → 下一步”的叙事闭环；
- 第一人称、真实数据、不过度包装 AI；
- 统一系列角标、字幕系统和数据卡样式；
- 每次说明本次记录如何影响下一次安排。

### 每期变化的内容

必须根据训练事实变化：

- 开头钩子；
- 主冲突；
- 重点动作；
- 数据证据；
- 视频时长；
- 叙事类型；
- 结尾悬念。

不得连续把每条视频都剪成：

```text
打开 Dashboard → 逐个展示所有动作 → 展示记录 → 结束
```

### 系列变化线

优先追踪 3–4 条已有正式数据支持的长期线：

1. 能力表现；
2. 疼痛与恢复；
3. 从乱练到理解动作目的的训练认知；
4. 计划完成率与现实调整。

没有测试或可比数据时，不虚构能力变化。可以明确说“目前还没有足够数据证明提高”。

### 已发布内容的去重

只有用户提供发布历史，或仓库以后存在明确的视频内容日志时，才进行主题去重和表现复盘。不得把“生成过方案”自动当成“已经发布”。

如果用户希望长期维护内容日志，应另行确认后再创建或更新，至少区分：

- 计划中；
- 已剪辑；
- 已发布；
- 发布日期；
- 标题与主题；
- 叙事类型；
- 播放、完播、互动等用户明确提供的数据。

## 13. 特殊情况

### 疼痛或异常症状成为主线

可以讲：

- 哪个部位、多少分；
- 在什么阶段出现；
- 因此取消或替换了什么；
- 后续准备观察什么。

不能讲：

- 未经评估的病因；
- “某动作治好了疼痛”；
- 一次训练无痛就已经康复；
- 鼓励观众照搬用户的调整处理自己的伤病。

### AI 推荐与实际不一致

这是高价值内容。结构优先使用：

```text
AI 基于什么给出建议
→ 现场出现了什么新信息
→ 为什么没有照搬
→ 实际怎样调整
→ 记录如何进入下次决策
```

表达重点是“AI 辅助 + 人做判断 + 真实反馈闭环”，不是证明 AI 永远正确或永远错误。

### 没有明显进步

不要强行制造结果，可以把核心改为：

- 为什么这次维持而不是加量；
- 计划与实际完成的差距；
- 首次建立基线；
- 暴露的新问题；
- 数据还不足以得出结论。

### 训练内容过多

只保留：

- 1 个主冲突；
- 2–3 个关键动作证据；
- 1 个结果；
- 1 个下一步。

其余动作使用 1–2 秒蒙太奇或完全舍弃。视频不是训练记录的完整副本。

### 用户素材与建议不匹配

用户明确列出已有素材时，分镜必须以现有素材为先。不得为了套模板要求重现一次已经结束的动作或失败。可以建议补拍不伪造训练事实的镜头，例如本人复盘、训练记录局部、装备、场馆外景或第二天的真实反馈。

---

## 14. 禁止行为

1. 禁止编造未拍到的镜头并写成“使用现有素材”。
2. 禁止编造动作、重量、组次、RPE、Readiness、疼痛、技术问题、情绪或现场对话。
3. 禁止把当日推荐、目标剂量或计划动作说成实际完成。
4. 禁止为了标题夸大训练结果、伤病风险或 AI 能力。
5. 禁止同时塞入多个互不相关的核心观点。
6. 禁止让开头先播放固定片头、完整 Dashboard 或长段背景说明。
7. 禁止连续朗读全部动作菜单和数据表。
8. 禁止用另一天素材冒充本次关键事件；作为通用示意时必须明确标注。
9. 禁止用不可比数据制作虚假的“前后提升”对比。
10. 禁止把短视频内容建议反写进正式训练数据源。
11. 禁止在不知道发布历史时宣称“这一题材此前表现最好”或“此前没有做过”。
12. 禁止推荐未授权搬运素材、音乐或字体。
