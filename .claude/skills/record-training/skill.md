# record-training

记录训练内容并更新所有相关文档（md + html 同步更新）。

## 使用方式

在聊天中直接输入训练内容即可触发，无需显式调用命令。触发词包括：`记录训练`、`训练记录`、`今天练了`、`训练内容` 等。

## 输入格式

用户应提供以下信息（自然语言描述即可）：

```
日期：YYYY-MM-DD
训练板块：力量/爆发力/速度敏捷/体能/篮球技巧 + 具体部位
训练内容分阶段描述：
- 准备阶段：具体动作 + 组次 + 负荷
- 激活阶段：具体动作 + 组次 + 负荷
- 训练阶段：具体动作 + 组次 + 负荷
- 核心训练：具体动作 + 组次 + 负荷
- 训练后反馈：各项评分 + 备注（用户未提及的评分项不填）
```

## 执行步骤

### Step 0：信息确认与补全引导

用户输入训练内容后，**首先确认日期是否正确**，再检查其他信息完整性。

**0a：日期确认（优先）**

- 如果用户提到的日期与对话上下文中的"今天"不一致，主动确认
- 如果用户输入了明确的日期但可能有误（如未来日期），委婉提醒
- 示例："确认一下，训练日期是 2026-09-10（周四），对吗？"

**0b：信息完整性检查**

如果存在以下信息缺失，主动引导补全：

| 缺失信息 | 引导提问示例 |
|---------|------------|
| 日期不明确或可能有误 | "确认一下，训练日期是 YYYY-MM-DD（周X），对吗？" |
| 缺少动作负重 | "哑铃弓箭步那组大概用了多少公斤/单边？" |
| 缺少组数/次数 | "六角杠铃深蹲做了几组？每组多少次？" |
| 缺少训练后感受 | "今天练完感觉怎么样——轻松、适中还是有些吃力？训练过程中有没有发现自己的薄弱点？" |
| 缺少评分/反馈 | "给自己的完成度打个分？核心控制、力量感这些方面感觉如何？" |
| 缺少动作细节（如只说了"练了腿"） | "具体做了哪些动作？六角杠铃深蹲、弓步蹲这些？" |
| 描述模糊（如"几个动作"） | "大概做了几个动作？分别是哪些？" |

**引导原则**：
- 一次最多问 2-3 个问题，避免一次性丢给用户太多
- 用户补全后继续检查，仍有缺失继续引导
- 如果用户明确表示"记不清了"或"没注意"，不要追问，按已有信息处理
- 不要替用户回答，所有数据必须来自用户本人

### Step 1：解析训练内容

- 从用户的描述中提取：日期、训练板块、各阶段动作（阶段名/动作名/组数×次数/负荷/备注）
- 如果缺少评分项，留空不填
- **CRITICAL：只记录用户明确提到的内容。动作名称、组数、次数、负荷、备注全部来自用户输入，禁止自己编造任何数据**

### Step 2：更新月度记录文件

目标文件：`records/YYYY-MM.md`

- 如果文件不存在，先按**初始化模板**创建新文件（含训练日历表格，预填当月所有日期的行，全部留空）

#### 2a：更新训练日历表格

- 在日历表格中找到对应日期行，填入训练内容（格式：`🏋️ [板块·部位](#训练详情-YYYY-MM-DD)`）
- 多条训练用 ` + ` 分隔（格式：`🏋️ [力量·下肢](#训练详情-YYYY-MM-DD) + 🏀 [篮球技巧·投篮](#训练详情-YYYY-MM-DD) + ⚡ [爆发力](#训练详情-YYYY-MM-DD)`）
- 标签/状态列根据训练总结填写关键信息（如：核心偏弱、弓步负重偏轻等），如果首次训练无明显弱点发现则留空

#### 2b：追加详细训练记录

详细记录位于训练日历下方，标题命名为 `### 训练详情 YYYY-MM-DD`。

格式模板如下（只写用户提供了的阶段，没提供的不写）：

```
### 训练详情 YYYY-MM-DD

**训练板块**：🏋️ ⚡ 🏃 🔄 🏀 （按实际选择图标，多个用 · 连接）
**状态标记**：`强度中等` （根据负荷/容量/反馈综合判断）

#### 准备阶段

| 项目 | 组数×次数 | 负荷 | 备注 |
|------|-----------|------|------|
| 动作名 | 组数×次数 | 负重 | 用户备注或动作要点 |

（如果有激活阶段则写 #### 激活阶段，同理训练阶段、核心训练）

**训练阶段的灵活处理**：
- 力量/爆发力训练：按标准四阶段（准备→激活→训练→核心）
- 篮球技巧/速度敏捷训练：只需「训练阶段」一个表格，按训练项目分行，如运球练习、投篮练习、实战等
- 体能训练：只需「训练阶段」，列出间歇方式、组次、时长
- 混合训练（如 Day 3 爆发力+篮球）：爆发力部分按标准阶段，篮球部分合并到训练阶段
- **只写用户有数据的阶段，没提到的阶段不写**

#### 训练后反馈

| 项目 | 评分（1-10） | 备注 |
|------|------------|------|
| （用户提供的评分项） | 用户评分 | 根据训练数据分析的备注 |

评分项**只写用户提供的**。如果用户没有提到评分，则省略整个训练后反馈表格。

备注撰写规则：
- 只分析用户数据中客观存在的信息
- 参考同一动作的历史记录做对比分析
- 举例正确写法：
  - ✅ "深蹲重量保持50kg，组次与上次一致"
  - ✅ "弓步蹲负重从5kg提升至10kg，完成度较好"
  - ✅ "弹力带侧走膝部热身后疼痛减轻"
  - ❌ "举腿时握力先于腹肌力竭"（用户没提到握力问题时不能写，即使是合理推测也要避免）
  - ❌ "下腹有明显酸胀感"（用户没提感知不能写）

#### 改进方向

> 基于本次训练数据给出的改进建议

- 结合本次训练中暴露的问题（组次完成度、负重合理性、动作控制等）给出具体可操作的建议
- 参考该动作的历史记录和进步趋势
- 如果有上次训练的改进方向，检查是否已修正，并记录

#### 训练总结与优化建议

> 对本次训练安排的专业、客观、全面分析

| 问题 | 建议 | 优先级 |
|------|------|-------|
| （本次训练安排中不合理或可优化的点） | （具体调整方案） | 高/中/低 |

分析维度：
1. **容量与强度平衡**：组数×次数×负重是否合理，不同动作之间是否匹配
2. **动作选择与顺序**：动作顺序是否符合生理规律（爆发力→大重量→辅助→核心），动作之间是否有冲突
3. **渐进合理性**：与上次训练相比，渐进幅度是否合理
4. **恢复与疲劳管理**：训练量是否符合当前恢复能力
5. **不足之处**：哪些肌群/能力未被覆盖，下次训练应补充
6. **纠正上次问题**：如果上次有训练总结，检查本次是否修正了之前的问题

### Step 3：更新主文档 training-log.md

#### 3a：更新训练概览

目标位置：`training-log.md` 的「一、训练概览」表格

- 如果当前月份已存在行：更新训练天数（计数该月文件中非休息日的训练日数量，格式 `N 天`）和覆盖板块
- 如果当前月份不存在行：新增一行

#### 3b：更新弱点追踪

目标位置：`training-log.md` 的「三、弱点追踪」表格

**第一步：回顾已有弱项，主动对比更新状态**

读取当前「三、弱点追踪」表格中的所有条目，逐条对比本次训练数据：

| 检查维度 | 判断方法 | 示例 |
|---------|---------|------|
| 本次是否训练了该弱项相关板块 | 匹配弱项的「所属板块」与本次训练板块 | 弱项板块=核心，本次训练包含核心训练 |
| 相关动作是否有改善 | 对比同一动作的评分/负重/组次变化 | 死虫负重从 5kg 降为自重后稳定性评分提升 |
| 用户是否提到该弱项的变化 | 用户发言中是否有"XX好多了""XX还是很差"等表述 | "死虫今天控制好多了" → 状态改善 |
| 是否有训练总结明确指出修正 | 上次训练总结的问题本次是否已修正 | 上次说"降负重"，本次确实降了且效果好 |

根据对比结果更新「当前状态」列：
- 有明显改善 → `改善中` 或 `已改善 ✅`
- 仍然存在 → 保持 `待改善`，可在备注中追加日期标注持续未改善
- 本次训练提供了新的相关数据 → 在备注中追加新信息（如 "09-10 篮球日反手上篮仍不稳定"）

**第二步：新增本次发现的弱项**

- 弱项必须是本次训练数据中客观反映出的问题
- 格式：`| 弱项描述 | 所属板块 | 本次日期 | 待改善 | 具体目标 | 备注 |`
- 如果弱项已在表格中存在（相同或高度相似的描述），不新增，只更新备注
- 如果本次训练未发现新弱项则不新增

**CRITICAL**：判断弱项是否"改善"必须基于客观数据（评分变化、负重变化、用户明确表述），不能凭主观推断。如果没有足够证据判断，保持原状态不变。不要强行把"待改善"改成"改善中"。

#### 3c：更新进步追踪

目标位置：`training-log.md` 的「四、进步追踪」

**第一步：更新已有指标**

- 对于本次训练中出现的动作，更新"当前"列为最新数据
- 如果有目标列，根据用户之前设定的目标判断进度
- 仅更新本次训练中实际出现的动作指标

**第二步：按需新增指标分类**

- 如果本次训练引入了新的训练板块（如首次篮球技巧、首次速度敏捷），在该板块下新增对应的指标分类表格：
  ```markdown
  ### 篮球技巧指标

  | 项目 | 基线 | 当前 | 目标 | 进度 |
  |------|------|------|------|------|
  | 控球感 | 6/10（2026-09-10） | — | — | — |
  ```
- 如果该板块分类已存在但本次有新的可量化指标（如之前的评分项），追加新行
- 主观评分项（如控球感、完成度）以评分/10 记录；客观数据（负重、次数）以实际数值记录

#### 3d：同步更新月度 HTML 文件

目标文件：`records/YYYY-MM.html`

**如果文件不存在**：以 `records/2026-09.html` 为模板创建新的月度 HTML。全局替换月份年份信息，生成当月的日历网格（正确计算该月天数和起始星期），训练详情部分暂时留空（只有第一个 h2 标题占位）。

**如果文件已存在**，做以下编辑：

**0. 修复日历链接硬编码问题（仅首次需要）**

检查 `<script>` 中 `buildCalendar()` 函数内的 `link.href` 是否为硬编码的单一日期：
- 如果是 `link.href = '#detail-2026-09-09'` 这种固定写法，改为动态生成：
  ```js
  const pad = function(n) { return n < 10 ? '0' + n : '' + n; };
  link.href = '#detail-YYYY-MM-' + pad(d);
  ```
  其中 `YYYY-MM` 替换为实际年月。此修复只需做一次。

**1. 更新 JS 日历数据**：在 `<script>` 标签内的 `trainingDays` 对象中，为对应日期追加或新建条目：
   ```js
   DD: { labels: ['板块·部位'], tags: ['标签'] }
   ```
   多条训练示例如：`{ labels: ['力量·下肢', '篮球技巧·投篮'], tags: ['核心偏弱'] }`

2. **追加训练详情区块**：在 `<!-- ===================== TRAINING DETAIL ===================== -->` 区域的最后一个 `</section>` 之前，追加新的训练详情 section。HTML 模板参考现有格式（id 为 `detail-YYYY-MM-DD`），包含：
   - 训练板块标签（tag-strength/tag-power/tag-speed/tag-cardio/tag-bball）
   - 状态标记 tag
   - 各阶段表格（准备/激活/训练/核心），有数据的阶段才写
   - 训练后反馈（评分圈，颜色按评分：7-10 green，5-6 yellow，1-4 red）
   - 改进方向列表（priority-badge high/mid/low）
   - 训练总结与优化建议表格

**CRITICAL**：所有更新的 HTML 数据必须与 Step 2 中写入的 md 完全一致。

**HTML 编辑技巧**（避免编码匹配失败）：
- Emoji 和中文等多字节字符在 Edit 工具中可能因编码差异导致匹配失败
- 优先使用**纯 ASCII 锚点字符串**做匹配（如 `<section class="section" id="detail-` 或 `<!-- =====================`）
- 对于 emoji/中文内容，逐个用小段纯文本替换（如先替换日期、再替换标签文字，一个 span 一个 span 改）
- 如果单次 Edit 报 "String to replace not found"，缩小 old_string 范围重试
- 新增训练详情 section 时，在 `<footer class="footer">` 之前插入，而非依赖 `</section>` 计数

#### 3e：同步更新仪表盘 dashboard.html

目标文件：`dashboard.html`

**0. 修复日历链接硬编码（仅首次需要）**

与月度 HTML 相同，检查 `dashboard.html` 中 `buildCalendar()` 内的 `link.href`，如果硬编码则改为动态生成。

**1. 更新统计卡片**：如果本次训练在当月，更新「本月训练天数」的 stat-value
**2. 更新覆盖板块卡片**：合并当月所有训练板块
**3. 更新日历 JS**：在 `trainingDays` 对象中为对应日期添加链接标签，`labels` 带跳转：
   ```js
   DD: { labels: ['<a href="records/YYYY-MM.html#detail-YYYY-MM-DD">板块·部位</a>'], tags: ['标签'] }
   ```
   当前月的日历才更新，非当前月不动。

**4. 更新最近训练卡片**：替换为本次训练的摘要（标签 + 评分 + 链接指向 `records/YYYY-MM.html#detail-YYYY-MM-DD`）

**5. 同步弱点追踪表格**：

将 `training-log.md` 中「三、弱点追踪」的完整表格内容同步到 dashboard.html 对应区域。包括：
- 新增的弱项行
- 已有弱项的状态更新
- 如果之前是占位空行（`—`），全部替换为实际数据

**6. 更新进步追踪**：

- 已有指标的进度条：更新 baseline 值和 progress-fill 宽度百分比
- **新板块指标分类**（如首次篮球技巧）：参考现有卡片结构，在对应位置新增 card（含 card-header + progress-item）
- 进度条颜色：力量→accent，核心→purple，篮球技巧→purple，爆发力→yellow，体能→green

**7. 更新防伤检查表**：

- 日期改为本次训练日期
- 如果本次训练用户提到 Level 2 激活动作 →「训前膝部激活」✅
- 如果训练内容包含单腿动作（弓步蹲/分腿蹲等）→「单腿稳定性」✅
- 如果以上都不涉及 → 对应项标为 `— 未涉及`
- 说明文字要与本次训练实际内容匹配，不要残留上次训练的说明

### Step 4：生成下次训练推荐

**CRITICAL 要求**：推荐必须基于以下三方面的完整分析，缺少任何一方都禁止输出推荐。

**必须分析的数据源**：
1. **训练计划**：读取 `training-plans.md`，确认当前采用的周计划模板（方案A/B）、训练日拆分逻辑、渐进方式
2. **至少过往三周训练记录**：读取 `records/` 下最近 3 个训练周的详细记录，包括：
   - 各训练日的板块分布（力量/爆发力/篮球技巧等的频率）
   - 每个动作的负重、组次变化趋势
   - 训练后反馈中的评分和备注
   - 训练总结中记录的问题是否已修正
3. **弱点追踪**：读取 `training-log.md`「三、弱点追踪」，确认：
   - 哪些弱项仍处于「待改善」状态
   - 哪些弱项与下次推荐训练日类型匹配，需要在推荐中针对性地安排
   - 本次训练新暴露的弱项
   - 弱点涉及的单侧/不对称问题（如"左侧核心弱于右侧"），推荐时应安排单侧训练

分析完成后，在文档更新完成后给出下次训练内容推荐：

**格式**：

```
## 下次训练推荐

### 计划安排

基于训练周期的下一天推荐：
- 推荐训练日类型：（如 上肢力量+核心 / 爆发力+篮球技巧+体能）
- 参考周计划模板：training-plans.md 中的方案A/B

### 推荐内容

（根据过往三周训练趋势和本次训练暴露的问题，给出具体动作、组次、负重建议）

推荐依据（必须逐条分析）：
1. **板块频率与周期合理性**：对比最近3周各板块训练频率，确保不连续两天练同一肌群，且弱项板块有足够覆盖
2. **渐进趋势分析**：对比最近3周同一动作的负重/组次变化，推荐合理的进阶幅度
3. **待修正问题检查**：检查最近训练总结中的问题哪些已修正、哪些仍未修正，未修正的要在下次训练中安排针对性调整
4. **弱点针对性训练**：列出本次推荐中如何覆盖弱点追踪中的弱项（具体动作→对应弱项）
5. **防伤训练**：必须包含 prehab 建议，结合近期膝盖等部位的状态和 Level 2/3 进度
```

**CRITICAL**：推荐的动作和重量必须依据训练计划文档中的数据，不能凭空编造不存在的动作或能力水平。如果用户从未练过的动作，推荐时要标注"新动作，从轻重量开始试"。

## 初始化模板

当需要新建月度文件时，使用以下模板：

## 禁止行为

1. **禁止编造训练数据**：用户没提到的次数、负重、动作、感知全部不能写
2. **禁止编造身体感受**：用户没提到的酸胀、疼痛、发力感不能写
3. **禁止推测不存在的情况**：如"握力先于腹肌力竭"这种用户没确认过的推测不能写入文档
4. **禁止修改用户明确提到的数据**：不能擅自改小/改大负重或次数
5. **禁止遗漏历史记录**：如果该月份文件已存在，必须保留原有所有记录，只做追加和更新
6. **禁止修改其他文件的结构**：除下述指定文件外，不能修改其他文档
   - 可修改：`records/YYYY-MM.md`、`records/YYYY-MM.html`、`training-log.md`、`dashboard.html`
7. **HTML 数据必须与 md 数据完全一致**：训练数字、评分、备注、改进方向、总结全部严格对应 md 中的内容
