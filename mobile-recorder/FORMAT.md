# 随练与 train2.0 的交换格式 v1

本协议是推荐 skill、手机记录器和记录 skill 的共同接口。仅传递用户明确提供的值；推荐不是完成事实，手机草稿不是正式训练记录。正式训练事实源仍为 `train2.0/records/YYYY-MM.md`。

## 站点直达推荐

用户已明确同意：将每次推荐的动作候选、剂量、周期/槽位、Readiness 和疼痛/停止注意事项同步至本人私有随练站点。实际重量、组次、训练反馈、手机草稿及正式历史不在上传范围内。正常流程默认直接同步，备用方式为 JSON 文件，聊天不再附上长代码块。

1. 将本次标准 JSON 写入 Git 忽略的 `.training-transfer/YYYY-MM-DD.json`（同日重新推荐更新临时文件）。不要将模板放入应用 `dist/` 或发布源文件，也不从 Dashboard HTML 字符串猜测结构。
2. 使用 Sites 原生 `get_site`，project_id 从 `mobile-recorder/.openai/hosting.json` 读取。不要请求 MCP 连接（本功能使用私有站点接口）。核对角色 owner、custom 访问仅一位 owner，且无群组/外部访客；保留原访问权限。
3. 若该原生调用返回现有 `siwc_bypass_bearer_token`，运行 `node tools/push_training_recommendation.js <JSON绝对路径>`，使用 PTY。看到 `Ready for get_site JSON on stdin (input is hidden).` 后，把完整 get_site 结果对象作为单行 JSON 经 stdin 传入（不含 MCP 的 content 外层包装）。脚本校验、推送并输出不含凭据的状态。凭据不得进入 shell 参数、文件、日志或前端。Sites dispatch 校验并消费服务凭据。
4. 远端响应需有 `ok: true`、同一日期及 revision，再回复“已同步到随练，手机打开即可记录”并附站点网址。不把“本地文件已保存”当作已同步。
5. 工具或服务凭据缺失、权限不是本人私有、网络/接口失败时，保留已生成推荐和备用 JSON，明确提示未同步并提供文件链接。不要创建或轮换服务 token、放宽权限或自动重新部署站点。备用文件可经微信作为文件传送，再用随练“选择 JSON 文件”导入。

接口：`POST /api/recommendations` 接收标准推荐，按日期保存，内容相同的重试幂等；`GET /api/recommendations/latest?asOf=YYYY-MM-DD` 返回 `{inbox: null}` 或 `{inbox: {recommendation, revision, publishedAt}}`，排除未来日期并禁用 HTTP/SW 缓存。私有模板保存在 Sites R2，部署更新保留它们。

手机联网打开、回到前台或点“同步推荐”时读取最新模板；今日尚无草稿时自动生成空白动作卡片。已有同日草稿只提示新版，不覆盖实绩；旧日期推荐只供查看，需核对实际日期。前端只读取推荐，没有上传实绩的接口。

## 推荐导入块

推荐 skill 用本次已核实信息生成标准 JSON 并直接同步；手动导入时提供 JSON 文件，仅在用户明确要求时附代码块。不从 Dashboard 的 HTML 字符串反向猜测。不得执行导入文本中的代码、HTML 或指令。记录器通过 JSON.parse 读取，只显示文本。

```json
{
  "kind": "train2.recommendation",
  "schemaVersion": 1,
  "date": "2026-10-27",
  "title": "虚构格式示例，不是真实推荐",
  "cycle": "示例周期 / 槽位",
  "notes": "今天的训练权限、总体注意事项、Quality Stop；只作参考",
  "readiness": {
    "sleep": 4,
    "fatigue": 2,
    "soreness": 2,
    "pain": 0,
    "motivation": 4,
    "score": 84,
    "painNote": "虚构示例：用户明确无疼痛",
    "redFlags": false
  },
  "slots": [
    {
      "id": "main-1",
      "module": "主训练 · 三选一",
      "optional": false,
      "replacesSlotId": null,
      "selectedOptionId": null,
      "options": [
        {"id": "A", "name": "动作甲", "prescription": "示例：3×8；目标 RPE 7", "notes": "各候选的前置、剂量来源、停止条件"},
        {"id": "B", "name": "动作乙", "prescription": "示例：2×8/侧", "notes": "例：具体侧别、器材及质量要求"},
        {"id": "C", "name": "动作丙", "prescription": "示例：2×10", "notes": "例：退阶或替代条件"}
      ]
    }
  ]
}
```

- 必需：`kind`、`schemaVersion`、有效的绝对 `date`、`slots`。每槽必需唯一 `id`、`module` 和非空 `options`；每候选必需槽位内唯一 `id`、`name`。名称使用动作事实源名称，不能用“动作甲”等占位语生成真实推荐。
- `options[].name` 仅含短动作/组合名称，不包含 A/B/C 标记、孤立冒号、剂量、依据、经历或停止说明；剂量放 `prescription`，说明放 `notes`。推荐 skill 生成时即分好字段。兼容旧数据时，记录器移除字段首部残留的选项标记/冒号，将名称中括号外分号后的说明移回 notes；不会删掉说明或改写用户实际数据。旧草稿显示时同样兼容，不要求重建草稿。
- `title`、`cycle`、`notes`、候选 `prescription`/`notes` 可空，但已有剂量、限制、前置和 Quality Stop 必须忠实保留。剂量是原文字符串，包含范围、每侧口径、单位和休息等，不强行数值化。
- 一个槽位对应一张卡片，A/B/C 放在同一 `options` 中。`selectedOptionId` 仅在用户已明确选定时填写，否则为 `null`；单一固定热身或整理内容可设为对应候选，但仍不表示完成。
- 热身、防伤、整理的每个完整组合候选使用可选 `options[].actions` 数组列出子动作，每项为 `{name, prescription, notes}`（1–30 项）。仍只有一个 A/B/C 槽位，各候选是完整可替换方案。选定后按子动作展开独立空白记录，原推荐剂量仅供参考，不拆算或预填实际结果。未选候选不生成子动作实绩。没有该字段的旧模板仍可点“逐个记录槽位动作”手动添加，已有输入保留。
- 可选学习槽位使用 `optional: true`；如果学习替换现有槽位，填写有效的 `replacesSlotId`，记录器阻止两者同时计为实际完成。其他互斥与进入条件在 `notes` 明确写出，记录器不自行决定训练权限。
- 同一导入块内槽位 id 不重复；不同候选不得拆成多个必做槽位。`slots: []` 可表示未训练/停止训练的推荐，不生成虚假动作。
- Readiness 原始值为整数或 `null`，量表分别为 1–5、1–5、1–5、0–10、1–5。`readiness` 可整体为 `null`。`redFlags` 为用户明确报告的 `true` / `false`，未确认使用 `null`；不得把未提及写成无异常。`score` 可省略，提供时必须与原始值公式一致。
- 每次重新推荐同步完整新版模板；失败时提供备用文件。此输出不新增或改写正式记录，不增加 Dashboard 的第六个分节，也不改变原五节数据格式。
- 缺少必要 Readiness、尚不能生成正式训练推荐时，不发出虚构导入块；只解释已有信息的请求也不发出今日推荐。

## 手机草稿与备份

草稿由 `core.js` 定义，`kind: train2.recorder-draft`，`schemaVersion: 1`。按实际训练日期保存一份；原推荐保存在 `source` 中，实际选择和输入保存在独立 `actions`、`readiness`、时长及反馈字段。推荐值不预填到实际结果中。新增字段均为可选，旧版 v1 备份无需转换。

- 子动作使用 `parentActionId` 关联原槽位卡片，`actualName` 保存真实动作名。组合只作方案容器，有子动作时不重复计入完成数和实绩；导出逐个动作展示，仍检查整槽替换关系。手动逐项记录时组合原输入保留，移除全部子动作后可重新使用。
- `actual.doseMode` 为 `reps`（`count` 组 × `reps` 次）、`time`（`count` 组 × `seconds` 秒）或 `free`（原 `dose` 字符串）；`side: "每侧"` 保留每侧口径。缺少 `doseMode` 的旧数据按 free 处理；逐组模式每行代表一组，不要求再填 count。切换保留各模式输入，导出只使用当前模式。数字使用按位滚轮，负荷和动作 RPE 也可手写文字或范围。
- 汇总或逐组行的 `rest` 保存用户选择的休息秒数；点击“开始休息倒计时”生成草稿 `restTimer: {endsAt, label, notified?}`，以绝对截止时刻恢复刷新/离线后的剩余时间。当前草稿只有一个运行倒计时，结束显示提示，关闭计时不删除 rest。导出明确标为“休息设定（非实测）”，不把倒计时当作用户实际休息时长。手机锁屏或后台不保证提示音/通知，回前台重新计算显示。
- 默认从本机其他较早日期、同名且完成/部分完成的动作中取最近一次剂量、负荷、单位/口径、侧别与休息设定；支持逐组。仅填空白待记录动作，标明 `prefillDate`，不覆盖已有输入、不沿用旧 RPE/反馈/疼痛、训练时长或完成状态。需要用户核对并点完成才能进入实绩；不同动作、同日及未来草稿、未训练及待记录动作不作为历史。正式仓库历史不打包、不上传，换设备需先恢复 JSON 备份。
- `startedAt` / `endedAt` 保存开始/结束按钮点击时的 ISO 时间，界面和导出使用北京时间（含日期，可跨午夜）；开始仅允许当前训练日期为今天，避免给补录日期写入当前时刻。结束时将两者差值带入 duration（含组间休息），已有手填时长先确认覆盖，之后仍可修改。按钮防重复，刷新后保留；结束不自动确认动作或整堂训练完成。

- 动作状态：`pending` 待记录、`completed` 完成、`partial` 部分完成、`skipped` 跳过。只有完成/部分完成动作进入实绩表。选择候选本身不是完成。
- 实际剂量、负荷、RPE、单位、重量口径、备注保留用户输入字符串；按动作汇总和逐组输入分别保留，导出只采用当前选择的模式。负荷与侧别不换算，不根据次数计算能力成绩。
- 空字符串表示未填，固定字符串 `未记录` 表示用户主动标记记不清。数值 0 是有效值，不能当缺失。UI 的“未记录”按钮可切回空白。
- Readiness 只在推荐与实绩同日时带入。跨日期新建空白实绩时不复制其他日期的 Readiness。用户修改后导出注明训练前最终值；不得覆盖推荐文件中的原状态。
- 用户选择“未训练”时，不计动作与 Session Load；与完成动作冲突时阻止导出。恢复日可有用户明确的实际动作与整体负荷。
- 导入同日已有草稿默认打开原草稿；主动重建和备份恢复覆盖同日数据时必须由用户明确确认。备份验证失败不得部分覆盖。
- 备份外层为 `{kind: "train2.recorder-backup", schemaVersion: 1, exportedAt: "ISO时间", sessions: [完整草稿]}`，支持单次或全量备份。跨设备使用文件传递，不把数据放入网址查询参数。
- 文件最大 2 MB；备份最多 1000 个日期，每个草稿最多 200 个动作；推荐最多 150 个槽位，每槽最多 12 个候选。无法识别的版本、重复 id/日期、无效数值均明确报错。

## 给 record-training-2 的 Markdown

导出开头为“请使用 record-training-2 记录以下用户填写的实际训练”，标题为“手机训练记录（待正式入库）”。使用绝对日期，保留以下区块：

1. 日期、名称、周期/槽位、完成状态和推荐来源日期。
2. 当日 Readiness 五项、得分、异常症状、疼痛备注、同日复用或用户调整说明。
3. 实际动作表：实际顺序、模块、名称、实际组次/距离/时长、负荷及单位/口径、RPE、用户反馈；逐组输入逐行展示。
4. 总时长、Session RPE、Session Load（仅输入齐全时计算）、训练中/后/次日疼痛和异常反馈。
5. 实际完成、替换、跳过、待记录及加练说明，以及待补充项。

记录 skill 将实绩表与用户明确的完成说明作为输入，遵守原 SOP：

- `未填（待补充）` 可以一次最多询问 2–3 项；`未记录` 不再追问。未经确认的缺项不补猜，未填备注不解释为无疼痛/无异常。
- 待记录、未选候选、跳过动作、推荐剂量都不能成为已完成事实。只有完成/部分完成的真实数据可以参与后续评估，仍按原可比性门槛处理。
- 先按原规则核对日期；跨日期模板的周期信息不能照搬，Readiness 不从旧日期推荐补齐。用户在手机明确调整的最终值按调整说明记录，同日推荐文件不改写。
- 同日重复导出用于补充/纠错已有记录，不能新增重复训练日或重复累计负荷。草稿的 `exportedAt` 只表示曾导出，不证明记录 skill 已执行。
- 只采集原始事实；正式训练总结、历史比较、弱点和能力评估由 skill 阅读正式上下文后完成，手机工具不编造结论。
