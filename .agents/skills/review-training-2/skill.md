# review-training-2

将真实训练整理成可追溯的复盘和下一步重点。先读仓库 `AGENTS.md`、`train2.0/athlete-profile.md`；仅讨论身体指标或变化时读 `body-metrics.md`。遵守个人限制、疼痛权限与资料更新时间要求。不作医学诊断，不从身体指标推导能力或负重。

## 区间与启动

- 正式周期为 2026-09-21 至 2026-12-13，默认正式 3 日版。周区间按周期起点连续 7 天，阶段为 W1–4 / W5–8 / W9–12。页面临时切换不改变复盘口径；用户要求另一正式周期/模式时先说明当前工具尚不支持，不能悄悄套用 3 日版。
- 使用 Asia/Shanghai 日期。没有指定区间时取最近结束的一周；默认请求恰逢 W4/W8/W12 结束时，同时复盘该周与该阶段。较晚调用时若最近结束周属于这些阶段结束周，也同时生成两份。
- “复盘本周”或提前指定阶段时，只分析截至今天已记录的数据，标为进展报告，不自动影响推荐。不将未来日子写成未完成。
- 不因到期提示自动生成报告。用户要求复盘时默认保存；明确“只分析/不保存”则只输出分析，不运行 save/sync，不改任何文件。超出正式周期的区间先澄清，不循环周期。
- 周复盘重执行与恢复，阶段复盘重目标进展、复测和下一阶段重点。需要补问时一次最多 2–3 项；记不清则保留未知，不要求补齐全部历史。

## 读取与分析

1. 读取 `records/00_摘要.md` 定位日期、`weakness-tracking.md`、`ability-assessment.md`、动作库 `00_索引.md` 和当前目标区间的 4 周计划区块。摘要、JS 和历史推荐不充当已完成事实；不得读取 `archive/` 或自动同步 train1.0。
2. 分批读取目标区间所有正式月度 Markdown 详情，跨月都要覆盖。本技能是周期分析，允许超出日常推荐的 1–3 天读取上限；对前后表现比较仅补读必要的区间外基线。能力评估只有当前最佳，不能当成近期状态或完整历史。动作剂量、进退阶与停止条件按需查对应分册，不全读 17 本分册。
3. 运行 `python tools/training_review.py draft --type weekly --start YYYY-MM-DD --end YYYY-MM-DD`（阶段用 `stage`）获取 JSON 草稿。草稿只输出、不保存；统计直接来自正式 Markdown。JSON 的 `stats` 与 `sources` 原样保留，摘要冲突以正式记录为准。只需统计时用 `stats` 子命令。
4. 逐一核对槽位。明确补做归属原槽位、同槽位不重复计数；完整/部分/明确未完成必须附正式证据。取消后补做以实际补做结果为准。恢复日、额外篮球不抵扣槽位，列入 `extraSessions`，仍纳入真实时长和负荷。只有正式记录明确已完整完成且无相反证据时才记 complete；不能仅凭训练日数或部分动作推断。无记录写 no-record，不能断言未训练；归属含混写 unknown。周末居家适配等按正式记录明确归属核对，不由脚本猜测。
5. 解读有效时长、Session RPE、Session Load、Readiness、训练前/中/后/次日疼痛及覆盖率。缺失不是零；已知负荷合计不是完整负荷。脚本拒绝不一致负荷，保留警告；数字带“约”须保留近似说明。疼痛原始文本可能有多个时点/侧别，回看 `raw`，不能由一个最大值认定恢复完全。睡眠/疲劳、篮球训练时长和高冲击暴露按正式明细分析，未记录的统计不可估算。仅测试和取消记录不计训练天，但可作为真实能力或状态证据。
6. 按个人目标分别写“有进展证据 / 待观察 / 无法判断”。比较同动作、变式、侧别、单位、器材及测试条件的起始与近期结果，历史最佳另外说明；不能因卧推负重增加但次数减少就认定更优，不能用 CMJ 组数代替跳高、命中数代替命中率、无描述代替弱点改善。无效或条件未知测试不进入能力结论。
7. 给出少量明确的“保留 / 调整 / 暂缓”重点，逐项列正式证据日期、原因、待验证指标。阶段重点在下一阶段有效；周建议在下一周有效，调整执行和恢复。疼痛、恢复、当日条件、长期限制和周期规则优先；不能机械按日期强制进阶。仅有资料依据的判断写明档案更新时间，与真实训练证据区分；身体测量注明各自日期和方法。

## 保存与边界

报告格式和命令细节读仓库内 `.codex/skills/review-training-2/references/report-format.md`（两套入口共用同一规范）。将草稿补成完整 JSON，使用文件工具写入工作区临时文件，不用 PowerShell 默认编码重定向 JSON。

运行 `python tools/training_review.py save --input <已核对的JSON文件>`：工具保存固定标识的 Markdown，生成可读正文和结构数据，并同步复盘索引与 Dashboard 镜像。重跑保留首次生成时间、更新时间必须递增；同区间只保留一个报告，报告未主动重跑时保持当时结论。保存前若正式记录改变，重新统计和核对，不绕过校验。

- 事实源是 `train2.0/reviews/*.md`；索引和 `assets/data/reviews.js` 是工具生成镜像，不手工维护另一套内容。仅使用已实施的结构。
- 不写训练记录、摘要、月度 HTML、records.js、推荐文件、能力评估、弱点或个人档案。发现这些文件需要纠错时指出对应正式流程，不顺带改动。
- 进展报告、待刷新报告、过期报告不自动供推荐使用。W12 报告不自动启动下一周期。
- 保存后运行 `python tools/training_review.py verify`、`node --check train2.0/assets/data/reviews.js`、`git diff --check`；核对报告、历史选择及证据链接。单次复盘不改 Dashboard 外壳或渲染代码。
- 回复包含区间、完整/进展状态、执行情况、主要发现、数据缺口、下一步及适用日期，并链接报告。只分析时说明未保存。不要把建议写成已发生的训练或已验证的改善。
